## 3.3.0

Readout 3.3 fixes what got in the way of reading, makes opening agent documents more dependable, and refines the typography.

## Fixed

### Following and reading position

- When you are at the end of a document, Readout follows the agent again as it appends, even when it adds a long section.
- Your place is kept when the paragraph you were reading is deleted, when you change the text size or width or resize the window, when the appearance switches between light and dark in a document with diagrams, when the "rewritten" notice disappears, and after printing.
- <kbd>N</kbd> and <kbd>⇧N</kbd> land on the change in long documents. Section links and the outline no longer place the heading under the toolbar, and the outline highlights the section you jumped to.
- Very tall blocks (long code, large diagrams) are marked read once you have seen enough of them.

### Change marks

- A document that grows a lot, such as an outline the agent fills in, is no longer treated as rewritten: every addition is marked.
- A file briefly emptied and written again (as some scripts do) no longer shows everything as new.
- Task boxes ticked while Readout was closed are marked when you open the document again. A document rewritten while Readout was closed now says so.
- Large rewrites of long documents no longer freeze the window for seconds.
- An open "removed text" popup stays open while the agent keeps writing.

### Live updates and opening

- Files under `/tmp` and other temporary folders now update live. Files on network volumes are checked reliably.
- A symbolic link such as `latest.md` follows its new target when the link is changed, and keeps its reading history.
- What you had read in the last seconds before quitting is no longer lost.
- A window whose first read failed loads the file once it becomes readable.
- `readout -b` and the Claude Code hook no longer switch the tab you are reading. When more than three new documents appear at once, Readout now opens the newest one instead of none.
- Paste, cut and undo work in the Find field. Find finds text anywhere in long documents.
- Settings says when another app already uses the global shortcut.
- The update check runs while Readout stays open, and turning it on takes effect immediately.

### Rendering

- Inline math and footnote references work in nested list items. Display math `$$…$$` works inside lists and quotes and right after a line of text.
- Dollar signs in links (such as `?$filter=`) no longer turn into math, and `\[WIP\]` stays text.
- A `</details>` that is not on its own line no longer hides the rest of the document.
- Images with `?raw=true` or `#gh-dark-mode-only`, and local images written as HTML, now show.
- Reference-style links follow their definition when it changes.
- Version strings such as `react@18.3.1` are no longer email links. Section links match GitHub's for headings with code. Files saved as UTF-16 open correctly.
- Copying text no longer includes `§`, code language labels or button text.
- Printing in dark mode prints dark text on white, diagrams included.

## Improved

- Diagrams keep their natural size: no longer blown up in wide windows or shrunk to unreadable in narrow ones; very wide diagrams scroll sideways.
- Brackets at the start of code blocks, table cells and paragraphs no longer stick out into the margin.
- More even spacing: headings in the middle of a document, code blocks and tables inside lists, rules and the footnotes section.
- Chinese and English mixed in one list keep a consistent line height. Japanese text uses Japanese glyph forms.
- Long URLs wrap instead of making the page scroll sideways. Inline code keeps its shape when it wraps. Wide tables show that they scroll.
- `diff` code blocks shade added and removed lines across their full width. The code block toolbar no longer covers code.
- The section link and change bar line up with the heading text. Highlighted text and keyboard keys have proper styles.
- Better contrast for tip and warning titles, front matter and code comments in light mode.
