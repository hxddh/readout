Readout 6 does less: a file opens without waiting for anything, opening one never runs anything, and only what really changed is marked.

## Improved

- **Files in a git repository open sooner the first time.** Readout no longer asks git about a file before showing it. To see what changed since the last commit, choose View ▸ Compare with Last Commit.
- **A document an agent writes again from the top marks only what changed.** When an agent empties a file and writes it back piece by piece, the parts that come back as you read them are no longer marked removed and then new.
- **A build or a package install in an agent folder no longer wakes Readout.** It ignores `node_modules`, `.git`, build output and the like there before they reach it.
- **Readout is about 1 MB smaller.**

## Fixed

- **Opening a file could run a command.** A folder set up for it (a git repository that names a command as the place to fetch from) could make Readout's git run that command when a Markdown file in it was first opened. Readout no longer runs git when a file opens, and when you choose Compare with Last Commit, git reads the repository on your Mac and nothing else.
- **A link in a diagram could take a Quick Look preview to a web page.** A click on one in a preview now does nothing; in Readout it opens in your browser, as any link does.
- **Long code blocks stopped folding after printing.** After a print or a PDF export, a code block of more than 3,000 lines shows its first 3,000 and a button for the rest again.
- **Text in raw HTML could lose words.** `<pre>retry once = true</pre>` showed only "retry"; text between HTML tags is now left as written.

## Removed

- **Comparing with a version Readout saw.** Readout no longer keeps the last 20 versions of each document; the ones it kept are deleted. View ▸ Compare With is now View ▸ Compare with Last Commit, and <kbd>⌘Z</kbd> still brings back what you had read.
- **Marking a file against its last commit when it first opens.** Choose View ▸ Compare with Last Commit instead.
