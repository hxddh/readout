# Design notes

Readout has one job: make long, frequently rewritten Markdown from AI agents comfortable to read.

## Pipeline

1. **Watch.** An FSEvents stream on the file's parent directory, with file-level events. Agents usually write a temporary file and rename it over the target, which breaks watchers that hold a file descriptor; watching the directory survives that. Changes are debounced (80 ms trailing, at most 400 ms during continuous writes). Half-written files (empty, sharply shrunk within a second of the last write, or ending mid UTF-8 sequence) are retried before rendering.
2. **Parse.** cmark-gfm via swift-markdown, off the main thread. Inline math is protected from Markdown parsing first. Emphasis follows the CJK-friendly amendment (markdown-cjk-friendly): `**注意：**这里` is bold. Where it decides differently from CommonMark (next to CJK characters, CJK punctuation and variation selectors only), the same pass puts an invisible marker beside the `*` or `_` run so cmark decides as the amendment does, and the renderer removes the markers. A line break between two wide CJK characters (not Hangul) renders as nothing, not a space. The document becomes a flat list of blocks: top-level nodes, with every top-level list item as its own block. Rendered HTML per block is cached by exact source and context, so a re-parse only renders blocks that changed.
3. **Fingerprint.** Each block has a fingerprint of its normalized source: trailing whitespace and blank-line runs removed, list markers unified, ordered-list numbers and checkbox state excluded (agents renumber lists and tick boxes; neither is a content change).
4. **Diff.** Myers diff on fingerprints finds unchanged blocks. Between unchanged blocks, deletions and insertions are paired into edits by token-bigram Jaccard similarity (characters for CJK, words otherwise), keeping order. A one-for-one replacement of the same block kind is always treated as an edit, and so is a block whose text is the start of (or almost all contained in) a new block of the same kind, or a paragraph whose text starts a new block of another kind: a block being streamed in that grew, split into several or became a table or code once complete. A short last block (`1.`, `- [ ]`, `|`) whose text is in the new block starting on its line was half written and is not reported removed. If less than 20% of the document survives, it is treated as rewritten; when a count of shared fingerprints shows that, the alignment is not computed at all. Myers' work is bounded: when the differing middle of two long versions is far apart, it is anchored on blocks that occur once in each (patience diff) and the gaps are diffed the same way; a gap of repeated blocks only is aligned by occurrence, greedily or run by run, whichever keeps most.
5. **Identity.** Blocks carry a session-stable slot. Unchanged and edited blocks keep their slot; inserted blocks get a new one. The web view only ever receives insert / replace / remove operations keyed by slot.
6. **Anchor.** Before a patch, the renderer records the first visible block and the offset into it; after applying, it restores that in the same frame. Edited anchor blocks restore proportionally. A ResizeObserver compensates for blocks above the viewport that change height later (diagrams, math, images).

## Change marks

Marks are relative to what you have read, not to the previous write. A block counts as read once at least half of it has been visible for 800 ms while the window is focused. The baseline is what you have read: the current version of every read block, the version last read of a block with an unread edit, no unread insertions, and the blocks of unread deletions as last read, where they were; when nothing is unread, that is the current version. Opening the file against it marks exactly what was still unread (the blocks of unread deletions stay removed and take no part in the alignment), so changes read before quitting stay read. It is stored per file (fingerprints, a similarity excerpt capped at 500 characters per block, the whole text of longer blocks, the block's source where it differs from the normalized text, and a flag on blocks of unread deletions) and survives restarts; baselines saved before sources were kept still load, compared as normalized text. Scroll-only position saves never rewrite an unchanged baseline.

An edited block carries a word-level comparison with its text as last read (`WordDiff`): the Markdown source of both versions (list markers, numbers and checkboxes as written, trailing white space left out), tokenized as CJK characters, letter and digit runs, white space and single punctuation, compared with Myers after cutting the shared start and end; long middles are compared line by line first, then word by word inside changed lines. A short unchanged run between two changes is folded into them so a rewritten phrase reads as one deletion and one insertion. Clicking the block's edit mark shows it under the block; a baseline saved before whole texts were kept shows that the earlier text is unknown. Removed blocks show their whole source.

## Rendering

The page is a single WKWebView served from a custom `readout://` scheme. Shiki (JavaScript regex engine) highlights code lazily; KaTeX and Mermaid load only when a document needs them. A spare, fully initialised web view is kept warm so a new window renders immediately.

One tuned look, no typography settings beyond the text size. The text column is at most 35 em of the body text, so it holds the same characters per line at every size: measured in WebKit on macOS, about 78 of Latin text in SF Pro and 36 of Chinese in PingFang, inside 70–80 and 34–40 (3.9's default 42.5 rem held 94 Latin characters, its View ▸ Wide Text some 127). Instead of a wider column, the text grows with the window: the reader's size up to a 900 px window, 1.25 times it from 1800 px, smoothly between (1280 px: 1.11, 1600 px: 1.19), so a large window is not a narrow column between wide margins. It is CSS alone (the root font size, `clamp()` on the window width), so it is decided before the first paint, in Quick Look too, and costs a resize nothing beyond the reflow itself; the place the reader left (the same block, the same share of it at the top) is kept across any number of resizes. ⌘+ and ⌘− multiply the automatic size and ⌘0 returns to it; code, tables and diagrams' text scale with it. In a window narrower than the column, it is the window less its gutters; wide code and tables still widen into the margins, a table also when its short cells wrap again to fit. In a table's cell an identifier is kept on one line only while the cells kept so leave a column of sentences room (about 40 characters together): otherwise the longest of them break after their separators. Inline code sits in the sentence: its x-height 0.9 of the text's whatever the monospace font (`font-size-adjust`), on a faint tint of the text colour, with padding that never changes the line height. A long path or identifier in inline code, and a long bare path in text, breaks after its separators only: ReadoutCore puts `<wbr>` after `/`, `\`, `.`, `-`, `_`, `::` and the like (not in its first three characters, not leaving fewer than five, not between digits), and keeps a part WebKit would break inside at a `-` of its own (`2026-08-08`, `phase0-1.md`) on one line; none of it is text, so copy and find never see it. A paragraph ending with a colon (`p.lead`) and the list under it read as one unit, the list close under it; at the top level the reader marks the paragraph when the next block is a list item (`lead-list`, decided again as the blocks next to it change), so the gap is the same where a chunk ends between them.

Reader chrome element ids always use the `ro-` prefix (`ro-doc`, `ro-rail`, `ro-notice`, `ro-empty`); document content must never create ids in that namespace. `Slugger` escapes any slug starting with `ro-` to `h-ro-…`, and fragment/link resolution is scoped to the document container so it can never land on chrome.

## Privacy

The page's Content-Security-Policy is the security boundary: it allows no `http:`/`https:` sources at all (`img-src`/`media-src`/`connect-src` cover only `readout:`, `self`, `data:`, `blob:`), so rendering a document can never send a network request no matter what markup it contains. `HTML.sanitize`/`gateRemoteMedia` is UX only — it turns common remote `<img>`/Markdown images into click-to-load placeholders.

Clicking an image placeholder posts `loadRemote`; the App downloads it with `RemoteFetcher` (ReadoutCore): an ephemeral, cookie-free `URLSession`, 15 s timeout, public hosts only (loopback, link-local, private and unique-local literals, local and single-label names, and non-canonical numeric hosts are refused, and every address a name resolves to must be public; checked before the request and on every redirect — a name that changes its answer between that check and the connection is the accepted residual risk), status, `image/*` and `Content-Length` checked on the headers before any body is accepted, and the 20 MB cap counted while streaming so an oversized body is cancelled as soon as it passes the cap. Bytes are kept in a 100 MB least-recently-used cache and served back over `readout://remote/<token>`. The cache remembers which address each image came from: while its bytes are kept, every page is told (`remoteKnown`) and draws that address from them whenever its block is drawn again, with no click and no request; one click on a placeholder makes the host's other placeholders offer to load them all. Video/audio placeholders open externally instead of proxying. Quick Look never enables remote loading and shows placeholders only.

The one subprocess besides the editor (`xed`): the first open of a Markdown file with no saved reading state that lies in a git repository (a `.git` folder or file at or above it) runs `git show HEAD:./<name>` in the file's folder, so what changed since the last commit is marked against that commit ("Changes since the last commit"). It runs only when `xcode-select -p` names an existing developer folder and `/usr/bin/git` exists (the `/usr/bin/git` shim would otherwise offer to install the command line tools), off the main thread, with a 1.5 s hard timeout and a 5 MB cap on its output; untracked files (git fails), Git LFS pointers, binary content and unchanged files are skipped silently, and files outside a repository never start it. Nothing is written to the repository and nothing leaves the Mac (`GIT_TERMINAL_PROMPT=0`, `GIT_OPTIONAL_LOCKS=0`; `show` of a committed blob reads the local object store only). The committed version becomes the file's saved baseline like any other read state (`GitBaseline`, `CommitBaseline`).

## Focus and resume

The window subtitle shows the file's status when there is one (deleted, could not be read, decoded as another encoding), else task progress when the document has task lists, and otherwise nothing in a window that shows a tab bar: there the tab's tooltip shows the file's path (`~` for the home folder). A window without a tab bar (System Settings' default "Prefer tabs: In Full Screen" opens documents in windows of their own) has no tab tooltip, so its subtitle shows the file's folder, and two `plan.md` windows differ in the title bar and the Window menu; the subtitle follows when the window joins or leaves tabs. The toolbar holds the sidebar button, a next-change button shown only while something is unread, and the find field. There is no text-width setting: the column sizes itself (Rendering). Mark All as Read (⌘K) is undoable (⌘Z, five levels): the document is shown again against the baseline from before, as reopening the window would show it; while the file is momentarily empty (an agent truncating before it writes) Undo waits. A heading's context menu offers Copy Link to Section, which copies a `path#anchor` link to the section. The saved reading position is excerpt-anchored: the first 120 characters of the top block are stored alongside the baseline, so resume survives block-index shifts from agent edits (falling back to the legacy saved index for older records).
